# App-owned UI development

Use this guidance for app-owned UI architecture, adaptation, and navigation work. Load the additional UI ownership, copy/presentation, or runtime documents routed by [AGENTS.md](../AGENTS.md) only when the affected surface crosses those concerns.

## App-owned UI, adaptation, and navigation

- Use resource-backed localized text for app-owned UI. Follow [Localization contract](localization.md) for text ownership and resolution at the presentation/output boundary; preserve MIDlet, user, and machine content according to that contract.
- Build new or materially changed app-owned presentation with Jetpack Compose Material 3 and the project theme/shared components. Keep intentional Android View, renderer, input, emulator, and Java ME API boundaries native when they still own platform or compatibility behavior.
- Preserve application behavior during incremental UI migration. Do not change Java ME API behavior merely to facilitate Compose.
- Derive layout decisions from the current container constraints, window size, and insets rather than device names or orientation alone. A compact landscape window remains compact; a portrait tablet may already have room for a larger layout.
- Select Android versions, window sizes, heights, orientations, themes, text scales, system bars, cutouts, gesture navigation, and IME states according to the platform and layout risks introduced by the change. Exercise minimum or target Android versions when version-specific behavior is material rather than as a universal matrix for every UI edit.
- Use adaptive components or multiple panes only when simultaneous content provides a concrete usability benefit. Preserve a clear single-pane fallback, readable line lengths, and stable selection when the window changes size.
- Add a navigation framework only when a flow needs independent destination history, deep links, results, or another navigation contract that existing application state does not already represent. Do not mirror pager tabs, filter/sort state, dialog visibility, or a controller-owned hierarchy into a second back stack.
- Keep one authoritative owner for navigation and selection state. When a route or selection already defines the current content, derive adaptive pane visibility from that state instead of synchronizing it with a separate navigator.
- Preserve the Library list/grid viewport, active collection route, scope, and search/chrome state when returning from contextual settings, dialogs, Search, or metadata editing. State must belong to the applicable workdir and collection identity; a scope change must not expose another workdir's data. Returning to a Library context must not produce a flash or a delayed viewport jump over active user input.
- Library title, scope/sort controls, and application rows scroll as one coherent surface in both directions. Partial scroll positions must not leave large blank gaps or cause rows to jump when header controls enter or leave view; short results expand their visible controls rather than reserving hidden-header space. Controls obscured by system bars must not accept touches. At large font sizes the brand wordmark and Search/Settings actions must remain readable and reachable.
- The Library scope picker unifies All Apps, Favorites, Recently opened, Recently added, and named Collections into adaptive tiles; the persistent horizontal quick-filter bar is retired. Quick views operate on All Apps only, and choosing one while browsing a collection exits the collection scope. Switching quick views starts the new result list/grid at the top while retaining the current chrome position. The selector always offers All Apps to clear a quick view. Search animates the active Library title row into an inline search field; the existing List/Grid displays matching results instead of opening a separate page. Its temporary query never mutates the Browse filter or scroll viewport, and it searches only within the open scope (all apps or the selected collection). Opening Search focuses the field and shows the IME. Back first hides the IME/releases focus, then exits Search, restoring the original Browse viewport. The leading Back arrow closes Search immediately; Clear deletes the query without closing it. Controller events target the visible search results rather than the inactive Browse selection.
- Library MIDlet cards keep titles readable and show at most two lines of optional description. Longer descriptions open the read-only MIDlet Details child page instead of expanding cards into long documents. Details preserves the underlying scope/search/scroll viewport and displays catalog metadata and play statistics immediately; descriptor attributes, declared permissions, MIDP/CLDC and retained-source JAR size are loaded asynchronously for the active workdir, with unavailable source details left explicitly unavailable. Edit metadata remains a separate action, and missing/corrupt descriptors must not hide otherwise available Library information.
- MIDlet App Actions uses one adaptive grid for selection, details, settings, collection, shortcut, export, reinstall, and delete. A contextual Remove from collection action may accompany collection controls; Delete remains last with a distinct destructive treatment and confirmation. Keep actions and controller navigation available in a portrait Material 3 sheet and short-window adaptive dialog, without conflating collection removal with uninstall.
- Collections are scopes of the single Library: switching from All apps to a named collection retains the same title, sort, list/grid, Search, selection, and app-action presentation. Quick views remain All-apps-only. Switching scopes preserves the All-apps Browse viewport and isolates member projections, navigation, and data by workdir. The floating action opens the membership editor in a named collection and the installer in All apps.
- The scope picker uses the available short-window height rather than a fixed percentage, keeping browse/collection tiles scrollable above its Manage collections action in landscape and resized windows. Show the quick-view tiles directly without a redundant picker heading; show the Collections heading only when collections exist, and keep the final tile clear of the Manage collections divider. Its compact tile columns adapt to width and font scale, with selected state and app counts where relevant. Manage collections retains compact collection rows as a separate Library child page for creating, renaming, and deleting collections, not a second application browser. Its destructive confirmation states that deleting a collection does not uninstall MIDlets. Membership can be edited by collection through a checkbox list or by app through a checkbox list of collections; a new collection created from an app action also includes that app. These operations change catalog membership only, never installed files. Preserve contextual Back, controller accessibility, and non-destructive database upgrades. A horizontal content gesture cannot switch root destinations or trigger unrelated actions.
- Hierarchical child pages use short directional motion and Back reverses its direction. Search expansion, modal dialogs and data/loading state changes retain distinct presentation semantics and must not delay the primary application launch interaction.
- Config uses Quick Settings as its root. Shortcuts open the corresponding setting chooser directly; the FPS shortcut opens the performance detail. Display, Graphics & performance, Controls, Media, and System are child categories with independent scroll positions. Display owns geometry, presentation and fonts; Graphics & performance owns renderer/effects and performance details, while immediate event processing lives with System compatibility. Back from a category returns to Quick Settings; Back from an advanced detail returns to the page that opened it. No persistent tab bar, rail, or pager is used, and no second navigation stack is needed.
- MIDlet Config exposes a compact profile status and contextual actions at the Quick Settings root, followed by six common shortcuts, five categories, and a separate root section for configuration reset and installed-MIDlet data deletion. Profile drafts expose only a draft-specific reset, not MIDlet data deletion; the virtual-control layout reset remains within Controls. The Quick Settings tile count adapts to available width and font scale; categories remain grouped settings rows. The screen-size chooser keeps its actions visible on short windows and lets the user toggle width/height reversal of the offered preset sizes without changing the saved MIDlet size until one is selected. Profile management uses adaptive lists and local menus, separate from per-MIDlet editing; shader effect catalogs similarly adapt across window sizes. A normal local edit never publishes to a shared named profile, while an explicit profile update may affect other linked MIDlets at their next preparation. Stopping a live named link preserves its local configuration and origin, without deleting the named source. Font remains a Display detail and performance a Graphics & performance detail; Settings Search navigates/reveals the existing option, including root actions, rather than making another preference store.

- MIDlet Config and global Settings share `PreferenceTextContent` for title,
  current value, and supporting explanation; `PreferenceNavigationRow` and
  `PreferenceSwitchRow` also keep interaction semantics consistent.
  Choice/number/slider rows remain
  scannable, show a shared decorative trailing chevron, and reveal their full
  help in the existing dialog; switches retain their distinct trailing control
  and essential inline guidance, while navigation/action rows also provide a
  visible opening affordance. Values are visually subordinate to labels.
  Screen-size help appears in the chooser, not duplicated in the geometry list. `PreferenceNotice` supplies neutral
  Info and persistent themed Warning/Danger without per-screen banners. System
  shows conditional timing/compatibility warnings, while generic system-property
  guidance remains in the editor. Preferences, search targets, and storage owners
  do not change.
- The Library Settings action opens global Settings directly, without an intermediate hub. Group global preferences by purpose: app appearance and language; Library icon presentation and Grid-only layout; in-game screen/power behavior and capture/haptics; storage and profiles; updates and diagnostics (including the Mascot Capsule 3D usage notice); and About/support. Do not duplicate per-MIDlet configuration or change persisted preference keys when regrouping. About and Updates are child pages of Settings; Back returns to the settings list. Diagnostics and voluntary support remain directly accessible there. Preserve the Library viewport when returning from the Settings activity.
- Grid-specific Library settings (icon size, spacing, and title visibility) stay available even when the Library is in List view. Their summaries identify the Grid-only effect. The grid icon-size presets change cell density and artwork limits; Standard preserves the original 88 dp minimum cell and 72 dp artwork cap. List rows remain unaffected.
- Internal full-screen Activities (global Settings, Profiles, MIDlet Config, Control Skin, Key Mapper, diagnostic list/detail, and app-owned File Picker) use the same 220 ms small horizontal slide and 180 ms fade on entry and the reverse exit. Scope the Android window motion to those page themes; do not apply it to the launcher, guest runtime, or translucent Memory Editor. File selection still preserves its own navigation and cancellation semantics. Android 14+ configures activity open/close transitions on the destination to keep predictive Back's commit phase coherent; older platforms use the scoped window animation style.
- Control Skin gallery/editor/inline-detail navigation uses short, paired transitions derived from its existing selection state; preview bitmaps stay available until the outgoing editor finishes and are then released. Its normal detail sheet retains Material motion. Memory Editor tabs use the same short directional motion rather than a second pager, preserving list positions and the outgoing Inspector snapshot while Back changes the active tab. Busy installer states and File Picker folder contents remain data-driven rather than being treated as navigation pages.
- At the Config Quick Settings root, Android owns system Back so predictive cross-Activity navigation can run; category/detail pages, Search and profile drafts intercept Back to preserve their behavior. Settings Search expands inline in the existing top bar, requests keyboard focus and displays matching options in place. Search dismissal restores the previous category/Quick Settings view without writing configuration data.
- The single-root Library and compact MIDlet Config have no permanent bottom navigation bar or rail. File Picker Cancel/Choose remain selection actions, not destinations. File Picker uses the same shared inline search field as the Library: opening Search replaces the title/path in place and focuses the IME; Back first dismisses input, then closes Search, while its leading arrow closes it directly. The normal toolbar orders Search, Sort, then Select all/Unselect all (where multiple file selection is supported). The selection action applies to visible search matches without discarding selections outside the filter. Folder creation stays as an explicit browser row rather than competing for toolbar space; empty directories still expose parent navigation and folder creation. Implementations may change state-saving, spacer/scroll accounting, animation, or component structure as long as observable contracts, ownership, and performance requirements remain intact.
- Use Material 3 adaptive pane scaffolds for verified list-detail or supporting-pane behavior when they fit the supported Android range. Test compact Back behavior, selection and process restoration, and transitions between single- and multi-pane windows.
- Use `AdaptiveAlertDialog` for short Material 3 decisions and `adaptiveDialogLayout()` for custom Compose modal surfaces. Keep the shared adaptive width policy, let height wrap content, and bound only overflowing bodies with a lazy container or `verticalScroll` so titles and actions remain reachable.
- A single discovered MIDlet retains a compact install confirmation. Batch install uses a fullscreen, inset-aware review and results surface, with the install/retry actions outside its scrollable list. The review shows concise application identity and status first; source paths and less common actions are accessible through row expansion and a selection overflow menu. Preserve planner consent, preflight identity checks, cancellation, and retry semantics rather than reimplementing those decisions in presentation.
- Keep `DropdownMenu` for short anchored choices. Use a custom constrained dialog or a full-screen destination for long forms; do not change presentation type merely because orientation changes. Modal scrims must cover the owning surface, hide underlying semantics, preserve Back/outside-dismiss policy, and remain usable with the IME and 200% text.
- Use the existing `TransientNoticeHost` for short foreground feedback in Compose-owned screens. Keep its state at the local screen/controller boundary instead of creating an application-global notification queue. Use `SnackbarHostState` when a real action such as Undo is needed; keep field validation in the form and progress on its owning screen. A platform Toast is a fallback before the Compose host exists, when a modal obscures it, or during navigation to another Activity. Avoid duplicate success notices for self-evident changes.
- Keep touch targets at least 48dp where practical, expose labels/state/actions to accessibility services, and avoid duplicate focus targets by putting selection/toggle semantics on the containing row while making its indicator inert.
- Keep UI work economical on low-end devices: move I/O and expensive transforms off the main thread, use lazy containers and stable keys for long data sets, remember derived work with complete keys, and avoid per-frame persistence, duplicate state, or decorative effects that trigger broad recomposition.
- Apply [Testing strategy](development.md#testing-strategy) and [Visual verification](development.md#visual-verification-and-screenshot-references) to affected UI failure modes, including Back/restore, modal overflow, dismissal, action reachability, and accessibility semantics.
- For internal app icons, prefer official Material Symbols when suitable; use a repository-provided helper when available before creating a custom icon.
